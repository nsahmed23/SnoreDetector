## 2025-03-05 - [60fps React State Cascade]
**Learning:** In audio processing applications (like the Snoreguard prototype), state changes triggered by `requestAnimationFrame` (e.g., updating a volume state 60 times a second) will cause the entire component tree below the state owner to re-render constantly. While standard React performance advice warns about premature memoization, in these specific 60fps hot paths, NOT memoizing static children (like `LiveStatsCard`) introduces massive overhead. Furthermore, high-frequency arrays operations inside the rAF loop (like processing FFT bins) must be fused into single passes to avoid unnecessary O(2N) computations in the hot path.
**Action:** When a parent component receives 60fps prop updates (like volume), immediately look for static/infrequently updating children to wrap in `React.memo()`. Always merge multiple `for` loops operating on the same raw array data inside a rAF loop.
